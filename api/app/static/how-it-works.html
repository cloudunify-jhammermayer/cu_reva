REVA / how it works

DocsStatusHow it worksInternal modules

TL;DR

REVA reviews every pull request on a connected repo. Open a PR or push to it, wait about 10 minutes, and you get a Check Run plus a PR review with inline comments on the exact lines. It judges the diff of files under custom_addons/; /full-review makes it read the surrounding code in the repo clone as well.

Pushing again re-reviews only what changed. Reply to any inline comment to ask why, or teach it with /dismiss and /mute. Nothing you do costs you anything; REVA's spend is capped per author and it waits by itself when a budget is full.

When it reviews

Automatically

On opened, synchronize (every push), reopened and ready_for_review.

10 minute debounce: every new push resets the timer, so a burst of pushes costs one review. Draft PRs are reviewed once they leave draft.

On command

Comment on the PR. Commands run immediately, no debounce. Only owners, members and collaborators can trigger a paid review.

A command works even on PRs opened before REVA was installed. /review-all widens which files; /full-review deepens how far REVA reads.

What a re-push does

After a first review, a new push gets an incremental review: only the diff since the last look, findings are re-checked and resolved threads stay resolved. A force-push still gets a delta when the base is unchanged; otherwise a full review.

What you get back

Check Run

success no findings, or info only. failure at least one finding at major or above (per-repo block_on_severity). neutral declined, or only findings below the threshold. skipped trivial change or superseded by a newer push. queued waiting for a budget.

PR review

A summary, a risk level (also set as a reva-risk-* label), and at most 15 inline findings with severity, category and a suggested fix where it makes sense.

Requirements check

If the PR closes GitHub issues (Fixes #12 or the sidebar link), each issue gets a verdict: matches, partial, does not match, unclear. Advisory only, never turns the check red.

Per-repo settings

A .claude-review.yml in the repo root, read from the PR's head commit:

block_on_severity
Which severity turns the Check Run red: critical, major (default), minor, none
max_diff_lines / max_diff_tokens
Size limits before a PR is declined as too large (default 2500 lines). max_xml_diff_lines / max_xml_diff_tokens add a stricter cap that applies only to XML-only PRs
skip_paths / review_all_paths
Exclude globs, or review every path instead of only custom_addons/
custom_instructions
Free text REVA follows for this repo ("we use Odoo 17, ignore the legacy module …")
odoo / odoo_version
odoo: true switches on the Odoo-specific reviewers; odoo_version (default "19.0") picks the Odoo core REVA grounds against
odoo_instance
Name of the Odoo instance whose release-log lookups may search this repo; leave unset otherwise
verify_findings
Second-pass self-check of blocking findings before posting (default on)

Copy-pasteable starting point; every key is optional.

# .claude-review.yml — REVA settings for this repo (read from the PR's head commit)

odoo: true                      # enables the Odoo-specific reviewers
odoo_version: "19.0"            # the Odoo core REVA grounds against; set your project's version

custom_instructions: |          # free text REVA follows on this repo
  We use the OCA queue_job stack; do not suggest cron-based alternatives.
  German UI strings live in i18n/de.po, do not flag them.

Budgets, in one breath

REVA pays for its own calls. Each author has a rolling 24 h review cap ($100); audits, replies and change notes share a global cap; each Odoo instance has its own. When a cap is full, or the Anthropic balance is empty, REVA does not fail: it parks the job, re-checks every hour, and resumes automatically for up to 2 days. The status page shows every waiting job, every cap, and the credit balance.
